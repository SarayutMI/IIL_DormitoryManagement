# อยู่ดี · IIL Dormitory Management

ฐานระบบจัดการหอพักด้วย **HTML + Tailwind CSS 4 + JavaScript ES Modules** ไม่มี React และไม่มี backend ในรุ่นนี้

หน้าระบบใช้ดีไซน์แนว Apple: system font, โทนขาว–เทา, สีน้ำเงินสำหรับปุ่มหลัก, เมนูโปร่งเบลอ และการ์ดมุมโค้ง รองรับการลด animation ตามการตั้งค่าอุปกรณ์

## เปิดใช้งาน

ต้องมี Node.js 20.11 ขึ้นไป

```sh
npm install
npm run dev
```

เปิด **http://127.0.0.1:4173** ข้อมูลตัวอย่างจะถูกสร้างครั้งแรก โดยใช้เดือนปัจจุบัน

ไฟล์ CSS ที่ build แล้วอยู่ใน `assets/styles.css` เปิดเว็บได้โดยไม่พึ่ง CDN การแก้สไตล์หรือเพิ่มคลาส Tailwind ให้รัน `npm run build` อีกครั้ง ใช้ HTTP server เพื่อโหลด JavaScript modules ไม่ควรเปิดด้วย `file://`

## ใช้งานได้ในรุ่นนี้

- แดชบอร์ด ห้องพัก สถานะห้อง ผู้เช่า และข้อมูลติดต่อ
- ค่าเช่าและเงินประกันแยกรายห้อง อัตราค่าน้ำ ค่าไฟ ค่าส่วนกลาง และรอบเดือน
- ค่าน้ำ/ไฟแบบมิเตอร์หรือเหมาจ่าย บันทึกมิเตอร์รายเดือน ตรวจเลขย้อนหลัง และเตือนหน่วยใช้สูง
- ออกบิลทั้งรอบ ป้องกันบิลซ้ำและเลขเอกสารซ้ำ เก็บราคา/ชื่อผู้เช่า ณ เวลาออกบิล
- รับชำระเต็มหรือบางส่วน เงินสด/โอนเงิน ประวัติรับชำระ ใบแจ้งหนี้และหลักฐานรับชำระ
- ยกเลิกบิลที่ยังไม่รับเงินพร้อมเหตุผล ปลดล็อกมิเตอร์และออกบิลใหม่ได้
- แจ้งซ่อม ผู้รับผิดชอบ ความเร่งด่วน สถานะ ค่าเสียหาย และนำค่าเสียหายเข้าบิลครั้งถัดไป
- สร้างสัญญา กำหนดระยะเวลาและเงื่อนไข ป้องกันช่วงสัญญาทับซ้อน บันทึกสถานะลงนาม
- ดาวน์โหลด Word **`.docx` จริง** และพิมพ์สัญญา/บิล/หลักฐานรับชำระเป็น PDF ด้วยเมนูเบราว์เซอร์
- ย้ายออก ตรวจยอดค้าง บันทึกหัก/คืนประกัน และเปลี่ยนห้องเป็นรอทำความสะอาด
- รายงานรายเดือน กราฟจากข้อมูลจริง ส่งออก CSV สำรอง/กู้คืน JSON และประวัติกิจกรรม
- หน้าจอรองรับคอมพิวเตอร์ แท็บเล็ต และมือถือ

## ฟอนต์เอกสาร

สัญญา ใบแจ้งหนี้ และหลักฐานรับชำระใช้ **TH Sarabun PSK** ทั้งหน้าพรีวิวและ PDF เนื้อหาขนาด **16 pt** หัวข้อ **20–24 pt** พร้อมหน้ากระดาษ A4 ฟอนต์ Regular, Bold, Italic และ Bold Italic อยู่ใน `assets/fonts/` และโหลดจากโปรเจกต์โดยตรง ไม่พึ่ง CDN

ปุ่มพิมพ์จะพร้อมใช้งานหลังโหลดฟอนต์ครบ เพื่อป้องกัน PDF ออกด้วยฟอนต์สำรอง ส่วน Word กำหนดชื่อ family จริง `TH SarabunPSK` ทั้งข้อความไทยและอังกฤษ ขนาด 16 pt และฝังฟอนต์ทั้งสี่แบบใน `.docx` ด้วยรูปแบบ OOXML รองรับการเปิดบนโปรแกรมที่อ่าน embedded fonts ได้ การแสดงผลอาจต่างกันในโปรแกรมที่ไม่รองรับฟอนต์ฝัง

ไฟล์ฟอนต์คัดลอกจากฟอนต์ TH Sarabun PSK ต้นฉบับในเครื่อง พร้อมลิขสิทธิ์และใบอนุญาตใน `assets/fonts/LICENSE.txt` แยกสไตล์เอกสารไว้ใน `assets/documents.css` เพื่อให้พรีวิวและ PDF ใช้รูปแบบเดียวกัน

## ลองขั้นตอนหลัก

1. หน้า **ตั้งค่าหอพัก**: กำหนดข้อมูลหอ อัตราน้ำ/ไฟ วันออกบิลและวันชำระ (1–28 ภายในเดือนเดียวกัน)
2. เพิ่มห้องว่าง → เพิ่มผู้เช่า → สร้างสัญญา
3. หน้า **จดมิเตอร์น้ำ–ไฟ**: เลือกรอบเดือน กรอกเลขก่อนหน้า/ปัจจุบัน แล้วบันทึกทั้งรอบ
4. หน้า **บิลและการชำระเงิน**: ออกบิลรายเดือน → ดูบิล → รับชำระเงิน
5. เมนูพิมพ์/PDF เปิดเอกสารในแท็บใหม่ กด **พิมพ์ / บันทึกเป็น PDF** และเลือกปลายทาง Save as PDF
6. หน้า **ตั้งค่าหอพัก**: สำรอง JSON เป็นระยะ หรือเริ่มฐานข้อมูลว่างสำหรับทดลองข้อมูลของคุณ

## กฎธุรกิจของต้นแบบ

- หน่วยใช้ = มิเตอร์ปัจจุบัน − มิเตอร์ก่อนหน้า; เงินปัดทศนิยมสองตำแหน่ง
- ค่าเช่าเต็มเดือน ไม่คำนวณรายวัน อัตราภาษี ค่าปรับ ส่วนลด หรือปรับหน่วยกรณีเปลี่ยนมิเตอร์
- บิลออกเฉพาะห้องที่มีผู้เช่าและมีมิเตอร์ในรอบนั้น รวมกรณีคิดแบบเหมาจ่าย
- รอบเดือนที่เลือกใช้ผู้เช่าปัจจุบัน ไม่ควรย้อนออกบิลให้ผู้เช่าที่เปลี่ยนคนไปแล้ว
- ค่าซ่อมที่ติ๊กเรียกเก็บและยังไม่รวมในบิล จะเข้าบิลถัดไปโดยอัตโนมัติ ไม่มีการเรียกเก็บซ้ำ
- หลังออกบิล ล็อกมิเตอร์และค่าเสียหายที่อ้างอิงแล้ว ต้องยกเลิกบิลที่ยังไม่ได้ชำระพร้อมเหตุผลก่อนแก้ไข
- บิลที่รับชำระแล้วไม่สามารถยกเลิก รุ่นนี้ยังไม่มีระบบคืนเงิน/ใบลดหนี้
- ย้ายออกต้องไม่มีบิลค้างหรือค่าเสียหายรอออกบิล ผู้ดูแลยืนยันว่าจดมิเตอร์/ชำระงวดสุดท้ายครบ
- สัญญาเป็นแม่แบบ ต้องตรวจและเติมเงื่อนไขก่อนใช้งาน การบันทึกลงนามเป็นสถานะ ไม่ใช่ลายเซ็นดิจิทัล

## การเก็บข้อมูลและขอบเขต

ใช้ LocalStorage key `yoodii-dormitory-v1` ข้อมูลอยู่เฉพาะ browser/profile/origin ที่ใช้งาน การล้างข้อมูลเว็บหรือเปลี่ยนพอร์ต/เครื่องไม่ดึงข้อมูลเดิมมาให้ ไม่มีบัญชีผู้ใช้หรือการแบ่งสิทธิ์ ข้อมูลและประวัติแก้ได้ผ่าน browser tools จึงยังไม่ใช่ระบบสำหรับจัดเก็บข้อมูลส่วนบุคคลหรือธุรกรรมจริงหลายผู้ใช้

การออกบิลเป็นการกดสร้างเอง ยังไม่รันอัตโนมัติเมื่อปิดเว็บ บิลต่างเดือนคงเก็บแยกกัน อัตราที่เปลี่ยนไม่แก้ย้อนหลังในบิลเดิม ประวัติกิจกรรมอยู่ในไฟล์สำรองเดียวกัน

ฟังก์ชันจากเอกสารต้นทางที่ยังอยู่ในแผน: backend/database, login/RBAC, tenant portal, booking, file uploads/หลักฐานโอน/ภาพมิเตอร์, LINE/อีเมล, ชำระออนไลน์, ทรัพย์สิน, ผู้มาติดต่อ, multi-branch, การแจ้งเตือนตามเวลา, สำรองอัตโนมัติ และ audit ที่ป้องกันการแก้ไข

## ตรวจสอบและโครงสร้าง

```sh
npm run check
npm test
npm run build
npm run test:browser
```

Browser tests ใช้ Chromium ของ Playwright (ติดตั้งด้วย `npx playwright install chromium`) หรือกำหนด `PLAYWRIGHT_CHROMIUM_EXECUTABLE` เป็น executable ที่มีอยู่แล้ว

```text
index.html              หน้าเริ่มต้น
src/app.js              UI / ฟอร์ม / routing / LocalStorage
src/core.js             กฎคำนวณบิล มิเตอร์ รับชำระ และข้อมูลตัวอย่าง
src/documents.js        เอกสาร HTML, DOCX (OOXML ZIP), CSV
src/styles.css          Tailwind source และสไตล์หลัก
assets/styles.css       CSS ที่ build แล้ว เก็บใน repository
assets/documents.css    รูปแบบเอกสารและหน้าพิมพ์ A4 ด้วย TH Sarabun PSK
assets/fonts/           ฟอนต์ TH Sarabun PSK สี่แบบและใบอนุญาต
scripts/serve.mjs       static development server
tests/                  การทดสอบธุรกิจและ browser workflow
docs/requirements.md    เอกสารความต้องการที่ผู้ใช้ให้มา
```
